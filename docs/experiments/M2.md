# M2：同节点正式 eBPF 转发

2026-11-16 已通过隔离 netns 验收。使用 M1 的真实 CNI、`bpf/datapath.c`、Go `internal/datapath` 加载器，而非 M0 固定地址探针。入口 `tests/datapath/run.py`；精简证据 `M2-results.json`；原始命令与 iperf 结果 `build/m2/`。

## 已实现

- CNI 创建的 Pod 通过 host-veth ingress 执行源 IP/MAC/附件检查。
- IPv4 TCP/UDP 候选解析、校验和、TTL、options/分片/GSO 分类。
- 已登记 Pod 对 + 明确 CT miss + FIB/邻居/端点身份核对后，更新 TTL、L3 checksum、MAC 并 redirect。
- CT hit/error、ServiceCIDR、未知端点、邻居未解析等原样回退 Linux；修改报文后的错误只 DROP。
- 目标 egress 对快慢路径均检查附件与目标；直接 redirect 使用 `skb->cb` 携带目标 ID/epoch，并在最终投递前再核对。此标记只在本节点直接转发中使用，不是跨节点线上协议。两个方向的实际快转均已观测到目标 `delivery_fast_seen`。
- C/Go ABI：key 16 字节、value 64 字节、config 32 字节；编译期断言与 Go 序列化 golden bytes 验证。
- 不可变 HASH 快照经 ARRAY_OF_MAPS 整张切换；先验证完整输入，创建并 freeze 新 Map 后再发布。pinned maps/programs 可跨加载器进程保留。
- PERCPU 原因计数；独立 `knd-datapath` CLI 用于本地实验，Kubernetes 生命周期将在 M3 接入同一库。

## 实际通过

双向 UDP 抓取 TTL=63、正确 MAC、有效校验和，redirect 与 delivery_fast_seen 对应；ICMP 内核回退；伪造源 IP/MAC、错误 IPv4 checksum、错误 UDP 长度、截断 TCP 被拒绝；TTL=1 回退；IPv4 options 与邻居缺失回退仍只减一次 TTL；iperf3 UDP 和 TCP 控制连接；DNAT 的 TCP/UDP 与反向传输；hairpin SNAT/DNAT；非法快照保留上一代；阻断目标不能通过慢路径投递；目标 egress 注入旧 epoch 后真正 redirect 的报文被拒绝，移除注入后恢复。

最后一项注入程序只存在 `tests/datapath/stale_epoch.c`。TC 测试链需要返回 `TC_ACT_UNSPEC` 才会继续执行后面的正式规则；返回 `TC_ACT_OK` 会结束分类。该行为按 [Linux cls_bpf 实现](https://raw.githubusercontent.com/torvalds/linux/v6.18/net/sched/cls_bpf.c) 核查并通过实验确认。

当前成果达到 R0：自研 CNI + 同节点 eBPF 转发原型。还不是 Kubernetes 完整网络插件。未在本阶段声称跨节点、完整 Service 门禁、全部 ACL/生命周期矩阵或性能提升已经通过。
