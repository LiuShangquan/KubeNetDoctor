# M5：ACL、身份与生命周期

2026-11-17 核心与补充身份验收通过。执行 `tests/kubernetes/lifecycle.py` 与 `tests/kubernetes/identity.py`，使用真实 K3s/containerd，不以模拟调用代替 CNI 生命周期。完整命令在 `build/m5`、`build/m5-identity`，精简结果见 [生命周期](M5-results.json)、[身份](M5-identity-results.json)。

- 按源/目标 Pod UID + TCP/UDP 协议发布方向性 deny。双向限制用两条反向规则表达。它没有连接状态、端口/选择器语义，不能称作完整 NetworkPolicy。
- 直连 TCP、Service TCP/UDP 被拒绝；同节点 Service 的源 TC 看见 VIP，DNAT 后由目标 veth egress 执行规则。跨节点目标独立发布规则时也阻断 TCP 和新 UDP tuple。
- 非首片仍按 IP 身份与 IP protocol 执行 ACL；非法协议更新 HTTP 400，已有策略继续有效。
- 按 UID 阻断本地附件，发布后回读绑定表；Pod 发起和宿主发起的流量均失败。清除阻断后恢复。
- Agent 停止期间 CRI DEL 仍删除自有 veth、释放 IPAM，保留 detached journal；Agent 恢复后清理 tombstone。Kubernetes API 对象删除完成不代表 CRI 已完成，测试等待实际内核/租约收敛。
- 10 批 × 10 个 Pod，共 100 次真实创建删除；每批检查 IP 唯一、UID 唯一，结束后租约、事务记录、自有接口集合恢复到基线。
- 故意更改自有 veth alias：Agent 先阻断旧 ID/epoch 并回读，再报告所有权漂移；不会擅自修改可疑接口。恢复 alias 后删除并重建附件。
- 在旧租约确实释放后调整 host-local 分配游标，使新 Pod 复用同一 IP：新 UID、ID/epoch 正确变化，旧 UID 阻断没有误伤新 Pod。

本地 API 只接受 root Unix socket，单请求 64 KiB，拒绝未知字段和多 JSON 文档。`kndctl status|doctor|counters|endpoints` 查看本节点；`kndctl policy FILE` 发布本节点策略。多节点由调用方逐个发布并检查 generation，不宣称分布式原子策略事务。

内核侧 ACL 按当前快照中的 IP 对匹配；UID→IP 的绑定由控制面维护。节点间 informer 收敛窗口存在，可信实验网络之外的身份认证/多租户安全不在本项目保证范围。
