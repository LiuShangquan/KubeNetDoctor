# M1：最小 CNI 与 Linux 路由基线

2026-11-16 实际通过。入口为 `tests/cni/run.py`，原始命令、返回值和结果在 `build/m1/result.json`，精简记录见 `M1-results.json`。

使用独立 mount/network namespace 执行真实 CNI 二进制和 host-local。实现 ADD、DEL、CHECK、VERSION，IPv4 /32 routed-veth、固定 link-local 网关、静态邻居、宿主 /32 路由，以及持久事务记录。此阶段必须显式配置 `standalone: true`，尚未连接 Agent 或真实 Kubernetes runtime。

通过：两 Pod 双向 ping（TTL 63）；重复 ADD 返回同一地址；CHECK 检测 MTU 漂移且不修复；8 路并发 ADD 地址唯一；重复 DEL；分配/接口/ready 阶段失败回滚；4 个 SIGKILL 点恢复（包括接口已创建但 alias 尚未设置）；未完成 ADD 重试；netns 已删除后 DEL；外部同名接口不被误删；最终 0 附件日志、0 地址租约。

实现中修正了三个真实问题：Go 正则重复次数上限；当前内核创建接口时没有保留 alias；默认路由在读取时表现为 `0.0.0.0/0`。所有权使用创建前持久化的随机 MAC、确定名称、alias 和已记录 ifindex 联合检查。

接口顺序调整：当前内核要求接口 UP 后配置 IPv4 路由，因此先使 Pod peer UP、保持宿主 veth DOWN，完成 Pod 网络配置；随后启用宿主端并安装宿主 /32 路由。M3 必须在宿主端启用前挂载阻断状态的 BPF 门禁，最后 commit 才开放附件。M1 仅验证无策略的内核基线。

Go 单元测试（含 race）和 `go vet ./...` 通过。没有把此结果称为 eBPF 转发或 Kubernetes 集成完成。
