# M6：VXLAN 控制与 eBPF 内层转发

2026-11-17 验收通过。先以 `vxlan-kernel` 运行，再受控回收附件切为 `vxlan-fast`；未实现在线模式迁移。Agent 在两节点控制 `kndvx0`：VNI 42、UDP 4789、nolearning、MTU 1450、基于 Node UID 的 VTEP MAC。VTEP 地址为各自 PodCIDR 基址 /32，host-local 不分配这些地址。

代码 `internal/network/vxlan_linux.go` 创建并核验设备归属、VTEP IP→MAC 永久邻居、MAC→NodeIP FDB。远端 PodCIDR 通过 VTEP 的 onlink 路由指向隧道；先配置 peer 再添加路由，撤路由后精确回收旧 peer。Linux 执行 VXLAN 封装/解封装；这遵循 [Linux VXLAN 静态 FDB 模型](https://docs.kernel.org/networking/vxlan.html)。

| 结果 | 证据 |
|---|---|
| Linux 隧道基线 Pod、Service、DNS、Agent 重启 | [基线结果](M6-baseline-results.json)，redirect 增量为 0 |
| 双向 eBPF 隧道转发 | [Service/快路径结果](M6-Service-results.json)，每方向源/目标各 1 次 redirect，内层 TTL=62，MAC/checksum 正确 |
| 外层与内层可见 | [抓包结果](M6-VXLAN-results.json)，外层 192.168.77.11↔.12 UDP4789/VNI42，内层为真实 PodIP；原始 tcpdump 在 `build/m6/vxlan-fast/outer-inner.txt` |
| MTU | IP 长度 1450 可达；1451 本地拒绝，避免错误宣称封装后仍可承载 1500 字节内层 |
| Service 回归 | ClusterIP TCP/UDP、DNS UDP/TCP、hairpin、长连接与后端切换、NodePort 均通过 |
| ACL 回归 | [ACL 结果](M6-ACL-results.json)，本地 DNAT 目标、跨节点目标、分片、UID block 与无效更新保留均通过 |

NodePort externalTrafficPolicy=Cluster 的 MASQUERADE 源地址由输出设备决定。本实验 Native 是 192.168.77.12，VXLAN 是节点 2 的 VTEP 10.244.1.0；两者客户端都收到 NodePort 地址的回包。没有硬编码相同源地址来掩盖真实拓扑差异。

当前只验证两台独立内核 VM 的固定模式；无自动混合路由、无加密 VTEP 认证。两节点仍共享物理机器与 QEMU socket underlay，不表示已测得真实跨机性能。
