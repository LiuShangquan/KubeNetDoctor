# M7：性能测量与一次未采用的优化

结论：已完成可复现的短时实验、程序耗时剖析、单项修改、正确性回归和复测。**未观察到稳定的吞吐提升，B3 未进入交付版本。** 原计划的长时/多并发/规模矩阵尚未完成；本阶段是探索性测量，不给出性能认证。

## 测量条件

同节点：WSL Linux 6.18.33.2，隔离 netns，客户端/服务器分别 taskset CPU 2/3，两台实验 VM 同时运行。每次 trial 建新网络与连接，避免旧 CT 状态污染。B0–B3 每组 5 次，顺序以 seed 17 随机；UDP 100 Mbit/s、应用 payload 128 字节、3 秒，TCP 单流 3 秒。UDP RTT 为 Python 持久连接 echo，预热 100 次后 2000 个样本；包括应用处理与调度。

| 组 | 路径 |
|---|---|
| B0 | 同拓扑 Linux 路由，移除本项目 TC hook |
| B1 | 保留入口/目标门禁，关闭快转 |
| B2 | 正式完整 BPF 路径，CT/FIB/目标校验全部保留 |
| B3 | 仅在本地 fast 标记与 ID/epoch 有效时，目标重用来源 IPv4 checksum 已验证结果；其他门禁保留 |

B3 由 `KND_FAST_VERIFIED_CHECKSUM` 编译开关控制，单独 ELF；普通 `make bpf`、Agent 镜像都不使用它。候选执行 M2 正确性用例通过，记录 [候选回归](M7-candidate-results.json)。

## 同节点结果

数值为五轮中位数；括号给 TCP 的最小/最大值。RTT 列是各轮分位数的中位数，不是把所有样本混合后重新计算的总体分位数。

| 组 | TCP Gbit/s（范围） | UDP Mbit/s | RTT p50 μs | RTT p99 μs |
|---|---|---|---|---|
| B0 | 55.451（53.559–55.831） | 99.990 | 30.690 | 92.667 |
| B1 | 52.735（49.866–53.335） | 99.992 | 31.157 | 83.475 |
| B2 | 53.104（52.437–53.502） | 99.990 | 29.729 | 88.510 |
| B3 | 53.217（51.036–53.516） | 99.989 | 33.524 | 102.706 |

UDP 被 offered load 限制在 100 Mbit/s，不能拿它判断最大转发能力。B2/B3 UDP 的 redirect/(redirect+各 slow) 为 100%；TCP 中位数分别 58.13%/58.08%，其他报文受 offload/CT 等条件影响回内核。B0 没有本项目 hook，快慢比例不适用；B1 为 0%。这些比例单位为 hook invocation/skb，不是物理帧。

## 剖析、假设和决定

先用 `knd-profile` 临时启用 BPF_STATS_RUN_TIME，通过程序 Runtime/RunCount 差值观察入口与目标成本；没有永久修改全局统计开关。假设同节点入口已核验的 IPv4 头在目标再核验存在重复成本，于是仅对有合法本地 fast 标记的目标路径做 B3。

五轮随机 B2/B3、每轮 6 秒统计窗口内运行 4 秒 UDP，得到平均耗时的中位数/范围：

| 程序 | B2 ns | B3 ns |
|---|---|---|
| knd_from_pod | 267.720（259.274–281.604） | 266.341（254.616–273.446） |
| knd_to_pod | 68.853（66.369–73.115） | 68.611（66.625–76.309） |

区间高度重叠，吞吐和应用 RTT 也没有一致改善。保留默认独立目标 checksum 检查，保留实验代码用于学习如何否定优化假设。程序统计本身有成本，这些数值不是无仪器条件下的纯硬件周期。

## 跨节点探索数据

两个 2 vCPU/4 GiB、Linux 7.0.0-43-generic VM，经 QEMU socket underlay；同物理宿主。每模式 TCP/UDP 各 3 次、每次 3 秒。背景负载未严格冻结，模式顺序也没有随机配对；Native 测量期间还有短暂构建任务，因此**不能据此排序 Native 与 VXLAN 性能**。

| 模式 | TCP 各轮 Mbit/s | UDP 各轮 Mbit/s | UDP 丢包 % |
|---|---|---|---|
| Native | 7253.76 / 8859.17 / 3546.32 | 91.66 / 92.02 / 88.24 | 8.25 / 6.69 / 10.42 |
| VXLAN | 7348.65 / 8298.00 / 8687.00 | 91.26 / 93.39 / 96.34 | 7.44 / 6.34 / 2.18 |

抖动和丢包如实保留，未给出原因归属。每轮保留两个节点计数和 iperf 原始输出。iperf 的 AppArmor 例外见 [环境记录](environment-incidents.md)。这里没有跨节点 B0/B1/ACL 矩阵，也没有吞吐优化声明。

## 复现与数据

在 WSL root、项目目录、工具链已激活时：

```bash
make build benchmark-bpf
python3 tests/benchmark/run.py --modes B0,B1,B2,B3 --rounds 5 --output comparison.json
python3 tests/benchmark/run.py --modes B2,B3 --rounds 5 --profile --output profile-comparison.json
# 保持当前集群固定模式，在专用 VM 内创建两个临时测试 Pod：
python3 tests/benchmark/cross_node.py
```

`build/benchmark/` 保留完整本地输出；[持久测量记录](M7-results.json) 保留每轮计数、iperf 数据与 RTT 样本，去掉冗长执行命令。报告没有 commit，因为工作目录尚未初始化 Git；交付文件使用 SHA256 清单固定。

后续若要得出性能结论，应使用安静环境、固定频率/offload/CPU、等条件随机配对、预热与至少 60 秒多轮、更多并发与包长，收集 CPU/softirq 和队列丢包，先定位瓶颈。未经这些工作，不在简历填写“提升 X%”。
