## 2. 容器网络 JD 到交付证据的映射

| JD 要求 | 优先级 | 项目中直接开发的内容 | 证据 | 能力边界 |
|---|---|---|---|---|
| Go 或 C 编码 | 必做 | Go CNI/Agent/策略编译；C TC 程序 | 源码、调试记录、错误路径测试 | 不是只调用工具生成配置 |
| K8S CNI 研发 | 必做 | ADD/DEL/CHECK、IPAM 委托、端点就绪协议 | runtime 实际调用、失败回滚、Pod 连通性 | 原型，非生产级完整 CNI |
| TCP/IP 与网络编程 | 必做 | 报文解析、双向 hook、有限 TCP 授权状态 | 包序列、握手/返回流/关闭/超时测试 | 不自研 TCP 协议栈；不安排独立 TCP 收发练习 |
| 控制面到内核 | 必做 | Kubernetes 对象编译成规则快照并发布 | 标签/策略变化导致实际通信变化 | 节点内发布一致，不承诺集群原子切换 |
| Underlay/Overlay | 推荐完整交付必须覆盖 | 原生直接路由；Linux VXLAN 的设备、路由、邻居、FDB 编排 | 内外层抓包、两种模式连通性与 MTU 对照 | 首版两种独立模式；自动混合选路后置 |
| eBPF 内核开发 | 必做 | TC L3/L4 访问控制、Map、连接授权状态和计数 | 真内核加载、verifier 日志、实际 PASS/DROP | 自研策略数据面，不等于自研完整转发栈 |
| 吞吐/时延优化 | 必做 | 剖析与至少一项有依据的优化实验 | 同条件前后对照、重复测量、负面结果 | 事前不承诺加速比例，不把过滤等同加速 |
| 可观测与定位 | 支持功能 | 规则版本、端点、原因计数、有限调试事件 | 能从失败测试定位具体模块 | 不建设独立诊断平台 |
| Cilium/Calico/Flannel 理解 | 学习与对照 | 固定版本阅读两种转发/控制路径，记录取舍 | 源码路径、数据路径图、差异解释 | 阅读不等于贡献；不要求同时深入三个项目 |
| 开源贡献 | 可选 | 复现真实问题，提交有价值测试/修复 | 可核查 issue/PR 与最终状态 | 不为凑履历提交无意义变更，不保证合入 |
| GPU 大规模网络经验 | 本项目不承诺 | 通用容器网络机制与受控负载实验 | 清楚说明实验规模 | 无 GPU/RDMA/真实千节点条件，不冒称训练网络经验 |

NetworkPolicy 不是这份网络 JD 明确列出的唯一功能；它是本项目选择的开发载体，能够串起对象编译、规则下发、报文处理和并发更新。补充 VXLAN 和性能实验，是为了避免项目只呈现 ACL 功能而缺少网络拓扑与性能深度。

JD 中把 eBPF/DPDK 一并称为内核态加速不够精确：DPDK 的典型 Poll Mode Driver 路线在用户态直接轮询收发。项目选择 TC eBPF，DPDK 只作为技术路线比较，不同时引入第二套数据面。[DPDK PMD 文档](https://doc.dpdk.org/guides/prog_guide/ethdev/ethdev.html)

## 3. 自研边界

| 内容 | 决定 |
|---|---|
| CNI 网络附件编排与恢复 | 自研，使用 CNI/netlink/netns 库 |
| 节点内 IP 地址分配 | 复用 host-local |
| 节点 PodCIDR 分配 | 复用 Kubernetes 节点网段分配 |
| Pod 之间基本转发 | Linux bridge/IP 路由 |
| VXLAN 封装/解封装 | Linux 内核实现；自研其控制与配置 |
| L3/L4 规则匹配与动作 | 自研 TC eBPF |
| Kubernetes 策略到内核表转换 | 自研 Go 编译器 |
| TCP 返回流授权状态 | 自研有边界的状态机；不宣称完整 conntrack |
| Service NAT/LB、BGP、RDMA、DPDK | 不进入当前必做范围 |

## 4. 分级成果

- R0：CNI/ACL 实验原型。能展示代码和真实报文处理，不宣称 NetworkPolicy 实现。
- R1：原生路由 CNI + 规定范围内的入站 TCP 策略 + 生命周期与性能基线，可作为首个完整项目成果。
- R2：增加 VXLAN、两种路径对照与经过验证的优化实验，作为面向这份容器网络 JD 的推荐交付。
